# Design decisions

Decisions made for the language and the library, newest last. The reason is kept with each one. Syntax, grammar and boundary changes are recorded here, in this repo, not left in the vault.

`G` rows answer the 12 grammar ambiguities of the First Slice note (vault: `41 TDL Reference/tess-dl First Slice.md`). The note leaves them to the `tess-dl` session: each takes the note's recommendation unless the Notes column says otherwise. The maintainer answered the open questions on 2026-11-02; they are G13 to G18.

## 2026-11-02 (grammar, plan step 1)

| # | Decision | Notes |
|---|---|---|
| G1 | **An unquoted value is one kind, `Word`**, whose text is the whole run (spaces inside kept, outer whitespace dropped). A word whose text is a number is a `Number`. | The rule "an unquoted value runs to the end of the line, the next `,`, a closing brace or a comment" implies one run. `Hello world` is one word; `1st` is a word; `16` is a number. |
| G2 | **In the metadata block every bare value is a `Word`**, never a number. `0.1` is the text `0.1`. | Versions are strings (ADR-0014 layout rule 3): `0.10` and `0.1` must not be the same value. |
| G3 | **Numbers are `16`, `-4`, `0.9`**: an optional `-`, digits, optionally `.` and digits. No exponent, hex, digit separators, leading `+`, `.5` or `5.`. A word that only starts with digits (`16px`) is a word. | Smallest set the shell's lengths and opacities need. More can be added later without breaking a file. |
| G4 | **`Call` starts at any word written directly against `(`**; the arguments are values separated by spaces, to the `)`, on one line. | The shell, not the parser, knows which call names exist, so it can say "unknown colour function". |
| G5 | **String escapes:** `\\`, `\"`, `\'`, `\n`, `\t`, `\u` plus four hex digits. Anything else is `tdl-bad-escape`. | As recommended. |
| G6 | **Line endings, tabs, BOM:** `\n` and `\r\n` are both accepted and each line keeps its own; a tab is whitespace; a leading BOM is accepted and kept; a lone `\r` is plain whitespace; a `---` line may have trailing spaces or tabs. | A lossless tree must keep all of them. The lone `\r` and trailing-space details go beyond the recommendation; they are the least surprising reading. |
| G7 | **A slot is on one line.** A line end before `}}` is `tdl-unclosed-slot`. | D54 of the vault's ADR-0014. |
| G8 | **A list may span lines;** items are separated by `,` or a newline, with an optional trailing `,`. | As recommended; matches how entries are separated in a block. |
| G9 | **`Children` is an ordinary block** and `Import` an ordinary property. Only `If`, `Else`, `For`, `In` and `Key` are reserved. | The parser stays free of the shell's meaning. |
| G10 | **Key characters:** a letter, then letters, digits and `_`. The same rule serves block heads, `For` variables and `Name:` values. | D4 forbids numeric keys. One rule for every name keeps `tdl-bad-name` simple. |
| G11 | **Maximum nesting depth is 64**, counting the root block as 1; blocks, `If`/`For` bodies and lists each add a level. | Proposed by the note. A stack-safe parser must reach it without a `RecursionError`. |
| G12 | **Trivia is kept in source spans, not modelled.** Comments are entries in their block in source order; blank lines and indentation live in the spans between nodes. | Keeps the tree small and makes the exact round trip a property of the spans (`lossless-roundtrip`). |
| G13 | **One more language code: `tdl-unexpected-text`**, for text that is not valid where it stands: a missing colon (`Width 32`), a key with no value, an `Else` with no `If`, a `For` without `In` or `Key`, an unclosed `(` in a call, a stray `{` in an unquoted value. The message and hint say which case. | Answers Q1 (maintainer, 2026-11-02). It makes 18 language errors; the vault's "17" and its `TDL Language` error table need the new row. |
| G14 | **In value position, a `#` followed directly by a non-space character is `tdl-bare-hash`;** a `#` followed by whitespace or the end of the line is a comment. | Answers Q2 (maintainer). `Color: #fff` is an error; `Color: # note` is an empty value (G16) and a comment. |
| G15 | **`{{ }}` inside a quoted string is plain text.** A quoted string never holds a slot; a template is written unquoted. | Answers Q3 (maintainer). Quotes switch slots off. |
| G16 | **A property with no value is an error** (`tdl-unexpected-text`). | Answers Q4 (maintainer). |
| G17 | **`Else` follows the `If` body's closing brace,** on the same line or after newlines and comments. | Answers Q5 (maintainer). |
| G18 | **The four extra codes are accepted:** `tdl-too-large` (over 1 MiB, checked before parsing), `tdl-too-deep` (over 64 levels), `tdl-unsupported-version` (the `TDL:` version is newer than the library's), `tdl-bad-encoding` (invalid UTF-8 in `load`, with the byte offset). | Answers Q6 (maintainer). Together with G13 the library has 22 codes. |

## 2026-11-02 (corpus, plan step 2)

| # | Decision | Notes |
|---|---|---|
| G19 | **`}}` rule.** An adjacent `}}` outside a slot and outside a string is always `tdl-double-close`, pointing at the first `}` of the pair, whatever the number of open blocks. | Keeps the rule lexical. `{{ {'a': {'b': 1}} }}` ends the slot at the first `}}` and the trailing `}}` is then `tdl-double-close`. |
| G20 | **Positions of the two vague "points at" rows.** `tdl-no-root` points at the first character after the closing `---` line, including its line ending (5:1 when `---` is line 4 and ends with `\n`; 4:4 if the file ends right after the `---`). `tdl-unexpected-text`: a missing value, at the first non-whitespace character after the `:` (the `#` of a comment, or the line end); a key with no `:`, at the first character after the key and its whitespace; an unclosed `(`, at the line end; `For` without `Key`, at the `{` that opens the body; `For` without `In`, at the first `{{` after the variable; `Else` without `If`, at the `Else`; a stray `{` in an unquoted value, at that `{`. | The note leaves both open; each position is the first character that does not fit. |
| G21 | **`tdl-bad-encoding` position.** Line and column are computed from the valid UTF-8 prefix before the first bad byte (line = 1 + newlines in the prefix; column = 1 + characters since the last newline). | The bad byte itself cannot be counted in characters. |
| G22 | **`canonical()` shape** (what `expect.json` `"canonical"` holds): `{"metadata": {KEY: VALUE, ...}, "root": BLOCK}`, comments dropped. Value: `{"word": text}`, `{"string": resolved_value}`, `{"number": 16}` (JSON int) or `{"number": 0.9}` (JSON float), `{"percent": 50}`, `{"call": name, "args": [value, ...]}`, `{"list": [value, ...]}`, `{"slot": text}` (exactly as between the braces), `{"template": [{"text": "Battery "}, {"slot": " battery.percent "}, {"text": "%"}]}`. Entry: `{"block": type, "entries": [entry, ...]}`, `{"property": key, "value": value}`, `{"if": slot_value, "body": [entry...], "else": [entry...] or null}`, `{"for": variable, "in": slot_value, "key": slot_value, "body": [entry...]}`. A metadata value is a `word` or a `string`. The runner compares `json.dumps(x, sort_keys=True)` of both sides, so `16` and `16.0` differ. | One shape for the runner and the shell to read; no positions and no comments. |
| G23 | **Edit cases** are three files: `<case>.tdl`, `<case>.expect.json` holding `{"edit": {"call": ..., ...}}`, and `<case>.result.tdl`. Calls: `with_metadata` (`key`, `value`), `without_metadata` (`key`), `with_property` (`block`: dotted path of `Name:` values as `Document.find` takes, `key`, `value`: the TDL text of the value), `replace` (`start`, `end`: character offsets, `text`). Every call returns a `Document`; `with_property` is run as `doc.find(block).with_property(key, value)` and the returned `Document` is the result. A refused edit is `{"edit": {...}, "raises": "tdl-no-name"}` with no `.result.tdl`. | The vault says an edit returns a new Document. `replace` offsets and the `with_property` return type are the choices the maintainer may want to change. |
| G24 | **Metadata insert rules for edits.** `with_metadata("UID", v)` with no `UID` inserts `UID: v` on a new line directly after the last metadata line whose key is `TDL` or a version key (`Shell`). With a `UID` present only the value bytes change. Any other new key goes on a new line directly before the closing `---`. A new line has no indentation and takes the line ending of the line before it. `with_property` adds `Key: value` on a new line after the last property of the block, with that property's indentation and the file's line ending there. | Keeps an edit to the bytes it must change (`lossless-roundtrip`). |
| G25 | **Cap entry.** With `Limits(max_errors=50)`, a file with 60 mistakes gives `len(result.errors) == 50` and the message of the last entry contains the text `50`. | The vault says only "the last entry says so". |
| G26 | **Step 3 follows the brief's row boundary.** Step 3 is the tree, the parser and `canonical()` on a parsed document; it is done when `loads` plus `canonical()` match for every `ok` case (`test_ok_case_reads_to_the_canonical_tree`). `dumps`, `load` and the byte-for-byte round trip are step 5 (`test_ok_case_round_trips_byte_for_byte`). `canonical()` on a document read from text is in the first release because the corpus needs it; the formatter and `canonical()` on a tree built in code stay out until API Open Question 3 is answered. | The brief lists `canonical()` under "Not in the First Slice", meaning the Python-builder use. The corpus is read by the shell and needs it on parsed trees. |
| G27 | **Calls count as nesting levels,** like blocks, bodies and lists: `f(f(f(...)))` deeper than 64 is `tdl-too-deep` at the `f` that passes the limit. | A call can nest inside a call, so without a level count a long run of `f(` would overflow Python's stack. G11 listed only blocks, bodies and lists. |
| G28 | **Step 4 follows the brief's row boundary.** `loads` is the step 4 check: it raises the first listed error with its code, position, related origins, message and hint (`test_error_case_loads_raises_the_first_listed_error`, all text cases). `tdl-bad-encoding` needs bytes, so its error is built by a private decoder in step 4 and `load` is wired to it in step 5 (`test_error_case_load_raises_the_same_first_error`). The full list through `parse` is step 7 (`test_error_case_parse_lists_every_listed_error`). | The brief says step 4 is done when the error cases pass, but `load` is step 5 and `parse` step 7; one test per step keeps each step checkable on its own. |
| G29 | **Every `tdl-unexpected-text` kind is documented and has a corpus case.** The reader had 24 places that raise it; the list in `language.md` now names all the kinds and where each points (G20 extended), and `tests/corpus/errors/` has a case for each. Also: a `#` or `,` inside a call is an error (a `#` followed by a non-space is `tdl-bare-hash`); an unclosed `[` points at the `}` or end of file that reaches it; a `TDL:` value that does not start with a number is `tdl-unsupported-version`. | Step 4's audit. These are positions and kinds, not new codes, so they stay inside the session's decisions. |
| G30 | **`dumps` returns the source text; `load` reads at most `max_bytes` + 1 bytes; a `str` that cannot be UTF-8 is `tdl-bad-encoding`.** `dumps(doc)` is `doc.text` (no re-rendering), `dump` writes it as UTF-8 with the byte-order mark kept. `load` refuses a longer input as `tdl-too-large` without reading it whole. `loads` on text with a lone surrogate raises `tdl-bad-encoding` at that character instead of `UnicodeEncodeError`. | The API promises `loads` raises only `TDLError`; a Python `str` can hold characters that no UTF-8 file can (found in step 4). The code's wording said "`load` only", which now means bytes or text that cannot be UTF-8. |

No questions are open.
